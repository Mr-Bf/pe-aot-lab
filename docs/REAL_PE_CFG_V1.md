# Chocolate Doom 原 PE：第一份有来源的控制流需求图

2026-11-03，本批完成 `real_pe_cfg_v1`：从固定 Windows PE 的入口及两个 TLS 回调做有界递归解码，建立指令、基本块、直接边、未解析边与逐根来源。**45,456条图节点的原字节和边界全部经过独立 LLVM objdump 核对。** 本批构建的 ARM64 辅助库负责静态解码；没有执行第三方PE、生成游戏AOT、实现新的Windows运行语义或测试游戏性能。

开发结论：Go进入TLS启动路径的可验证ABI纵切，并继续由未知控制流前沿驱动扩展；当前部分图不足以进入完整游戏构建。实际第三方成功迁移数仍为0。前批固定的输入、许可与原始导入库存保持不变，见[输入基线](REAL_TARGET_INVENTORY_V1.md)。

## 输入、工具与固定身份

输入仍是官方Chocolate Doom 3.1.1 Win64的 `chocolate-doom.exe`，875,520 B，SHA-256 `15e81c194df270fbd71450222e71846247926fabfb889e72e7d855903454d752`。没有更换为重编译或简化样本。PE Entry RVA `0x13e0`；TLS数组的原始次序是 `0x1570`、`0x1550`，三者独立作根。

解码器复用已有CPU依赖中的XED静态库和78个头文件，原库/头文件摘要逐项匹配既有deps构建回执；实际源码归档也重新核对，固定XED commit为 `dc6bdbe036515c7ef55d3b2d50bafc5232bfe534`，Apache-2.0许可。新模块只包含原创适配器，不把XED归档、头文件或dylib加入公开源码。通过Clang编译小型C shim，Python ctypes调用，避免逐指令启动子进程；不重建LLVM/Remill。

最终本机解码器为 `build/real-pe-cfg-v1/decoder-02/decoder.json`；dylib为ARM64 Mach-O，CPU type `0x0100000c`。采用 `XED_CHIP_ALL` 识别模式，保留CET/MPX/LZCNT等特征相关opcode。该模式不是目标CPU能力/运行状态的证据，未支持的控制语义仍记为前沿。构建回执绑定适配器、库、头、Clang、SDK设置及产物摘要；是受信本机构建证据，不是未知第三方dylib的安全验证器。

| 项目 | 最终结果与边界 |
|---|---|

| 基本块 / 边 | **11,286 / 53,288**；CALL后继含明确的may-return假设 |
| 原始XED instruction class | 128类；未执行当前lifter的全部prefix/operand/flags/ABI准入，不能算支持率 |
| 按根的语法可达节点 | entry 45,329；TLS第0项124；TLS第1项94；有重叠，不能相加当独立指令数 |
| IAT静态控制引用 | 230条指令关联193个不同导入符号；只识别槽位置，未证明运行时目标 |
| 未闭合/特殊控制项 | 285个间接CALL，191个间接JMP，1个未建模INT，1个UD2停止点，共478条 |
| 元数据候选 | 1,554个RUNTIME_FUNCTION记录，全部只作候选，未自动seed |
| 冲突/限额 | 本目标0重叠冲突；指令/根/来源限额均未触发；只说明本轮图没有这些分析失败 |

间接CALL会同时保留未知callee边和may-return后继；不能由后继被解码推断callee会返回。间接JMP没有普通fallthrough；RET没有补造到全部callsite的返回边。条件分支的两条边未做可行性判断。异常/语言handler、动态加载产生的新代码与其他线程入口没有被自动覆盖，整图状态始终为 `PARTIAL_STATIC_GRAPH_NOT_EXECUTED`。

## 已定位的真实启动需求

| 原字节位置 | 观察 | 下一实现含义 |
|---|---|---|
| `0x13f1` | direct CALL到`0x1010`，may-return到`0x13f6` | 这是入口的静态边，不是已执行CRT初始化 |
| `0x1025`，`6567488b00` | GS + 32位地址覆盖的MOV | 需要明确Windows TEB/段地址语义；不能把GS地址当普通host指针 |
| `0x1052`，`f0480fb133` | 单条5B `CMPXCHG_LOCK` | 原子/内存序与flags需求；旧v7明确不准入该形式 |
| TLS helper的`0x2107` / `0x20c7` | 分别静态引用InitializeCriticalSection / DeleteCriticalSection的IAT槽 | 可从固定TLS reason集合设计小范围启动/清理合同，尚未执行 |
| `0x2120`，`dbe3` | FNINIT | x87初始状态需要明确建模；解码成功不表示已有执行实现 |
| `0x15c8` | CALL RAX | 图保留未知目标；前面两个LEA为同一地址，独立笔记提示可做局部常量证明，但本工具尚未实现路径裁剪 |

还观察到UCRT初始化/参数/内存接口、SetUnhandledExceptionFilter以及通过寄存器调用的API候选。仅凭静态出现不称必经路径。目标此前已含318个静态导入和32个随包DLL，本图没有实现它们；原生SDL/音频/图片库桥接的ABI与许可闭包仍待设计和验证。

## 验证与独立复审

最终 `discovery-02` 包含18项图算法、25项真实/分类解码器、4项CLI边界，共 **47项测试**，普通与`-O`各通过且无skip；两次原目标图JSON逐字节一致。冻结源码执行前后未变，报告SHA为：

`98b06b299a84a348e38c1c4ff96afb60624427a7cb62047b622704e708dcaea5`

独立oracle使用Apple LLVM objdump读取整个`.text`作为对照数据，不把线性输出当CFG。98,784打印行有一处把LOCK前缀单列；显式按原字节归并后为98,783条线性解码观察。最终图的45,456个节点全部找到相同边界/字节，未匹配数0；8,840个直接控制目标通过原位移字节独立算术，230处IAT引用、11,286块与53,288边的结构复核通过。另有三个启动窗口的1,791条指令与最终XED交叉；这些与全图检查重叠，不能相加称新增覆盖。

复审产生并修复的具体问题：

- 初版测试预期 `CMPXCHG`，固定XED实际枚举为 `CMPXCHG_LOCK`。修正测试以保留真实枚举；没有拆掉LOCK来让测试通过。
- 默认XED模式会把某些特征指令显示为旧别名；显式识别政策现写入回执。CLI/STI的XED RING0标记不足以代表其权限条件，适配器另设明确前沿。
- 图算法原先只检查已成功解码指令的字节所有权，可能漏报“早先解码失败的目标落入后来发现指令内部”；独立原始反例复现后修复，旧失败与新冲突记录均保留。
- 除指令上限外，增加64个分析根、500,000个来源对上限；超过后保留声明/节点并标不完整。独立小反例验证没有把限额触发伪装成完整结果，未做大内存压力实验。
- uint64 PC回绕、已知目标内部冲突、基本块分区与出口边均单独复核。两个原始合成PE仅作为静态数据送入XED，没有执行。

初版 `decoder-01` / `discovery-01`、旧测试错误、`graph-review-01`保留，最终证据见 `decoder-unit-01`、`discovery-02`、`graph-review-02`、`oracle-01/final-checks.json`。完整大JSON/objdump保留本机，私有Git只选紧凑结果/身份索引与文本证据；公开版不含PE、辅助dylib或大型分析产物。

公开源码工作副本另以其自身C源码构建 `public-decoder-01`，使用同一明确指定的已有XED依赖；47项测试普通／`-O`无skip通过，并重新分析相同原PE。只排除解码器构建身份这一字段后，两份完整图精确一致，其他字段没有忽略；证据为 `public-check-01/result.json`。本轮共构建三个小辅助库（初版、修正版、公开源码版），未构建游戏AOT；此验证不是网络clone、冷缓存、独立机器或游戏App复现。

## 开发入口及下一验收

入口为 [real_pe_cfg_v1](../real_pe_cfg_v1/README.md) 的 `build-decoder`、`analyze`；具体合同见[独立CFG审查](REAL_PE_CFG_CONTRACT_V1.md)。`analyze`的退出2表示部分静态图或明确拒绝，不是工具崩溃，也不应改成成功迁移退出码。旧生产install v3／migration v7保持冻结，本批没有放宽其准入或修改其运行时。

下一主线先建立**原TLS根→helper `0x2010`的reason/状态/ABI合同**：明确TEB/TLS、初始化次序、critical-section生命周期、FNINIT和回调返回行为；将`0x15c8`等间接前沿作为待证明项。只对有显式局部证明的边做裁剪，保留不成立的前提和原图。随后再以原PE、固定寄存器/内存输入和独立语义对照开展小切片AOT；不能把直接重编译游戏源码或替换自制样例计为目标迁移成功。

完整CRT启动、一般间接调用/多模块、SIMD/浮点语义、SDL/API与素材、实际窗口/声音/存档、长时稳定性和Wine/Rosetta同场景性能仍待验。这次关闭的是“缺少原入口驱动的指令/CFG需求图”，没有关闭游戏执行与性能阶段。当前不需要Steam登录或新游戏源码。
